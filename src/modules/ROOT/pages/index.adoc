== Conformance
The key words "MUST", MUST NOT", "REQUIRED", "SHALL", "SHALL NOT", "SHOULD", "SHOULD NOT", "RECOMMENDED",  "MAY", and "OPTIONAL" in this document are to be interpreted as described in <<RFC2119>>.

For recommendations -- i.e. "SHOULD (NOT)" and "(NOT) RECOMMENDED" -- the principle of https://en.wikipedia.org/wiki/Comply_or_explain["comply or explain"] applies: not complying is allowed but requires explaining why.

== Anatomy

Each *dataset* MUST be encoded as an _RDF dataset_ which contains exactly two graphs:

* a _named graph_ containing the data, which will be referred to as the *data graph*
* the _default graph_ containing the dataset (meta)data

The RDF dataset SHOULD be serialized as a _JSON-LD document_.

.Anatomy of JSON-LD document representing the dataset
[source,json]
----
"@id": ..., <1>
"@type": "dcat:Dataset", <2>
<3>
"@graph": [
    ... <4>
]
----
<1> The IRI of the dataset.
<2> The type of the dataset is `dcat:Dataset`.
<3> Metadata about the dataset. These statements are contained in the default graph.
<4> The data graph object. These statements are contained in the data graph.

[#metadata]
== Metadata

A dataset MUST declare an IRI which dentifies it. This IRI is RECOMMENDED to be a URN wrapping a UUIDv4 using the `uuid` namespace.

Furthermore, a dataset MUST assert its type to be `dcat:Dataset`.

WARNING: If the dataset type is not asserted to be `dcat:Dataset`, automated validation will not be able to target the data properly and yield false positive results.

Finally, the following metadata properties SHOULD be provided by each dataset:

|===
| Label | IRI | Type | Allowed cardinality | Description

| Issued
| `dcterms:issued`
| `xsd:date`
| 1
| Date the dataset was issued, i.e. start of the period of its validity.

| Title
| `dcterms:title`
| `xsd:string` or `xsd:langString`
| 0..1
| Title of the dataset.

| Publisher
| `dcterms:publisher`
| IRI from https://modellen.netbeheernederland.nl/controlled-vocabularies/market-parties[Market Parties]
| 1
| The publisher of the dataset.

| Conforms to
| `dcterms:conformsTo`
| IRI or `xsd:anyURI`
| 0..n
| Reference standards, vocabularies or models this dataset conforms to.

| References
| `dcterms:references`
| IRI
| 0..n
| Other datasets or data products this dataset references (depends on). For any non-boundary datasets this is the `@id` of the boundary dataset being referred to.
|===

=== Validation

The metadata requirements have been encoded as constraints in the {dataset-metadata-shacl-url}[Dataset Metadata SHACL] which can be used to automatically validate whether datasets satisfy the metadata requirements.

CAUTION: SHACL validators expect graphs, not RDF datasets. When an RDF dataset is passed as data graph to validate, many validators will use its default graph.
