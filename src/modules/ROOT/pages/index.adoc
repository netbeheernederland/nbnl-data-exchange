== Anatomy

Each *dataset* MUST be encoded as an _RDF dataset_ which contains exactly two graphs:

* a _named graph_ containing the data, which will be referred to as the *data graph*
* the _default graph_ containing the dataset (meta)data

The RDF dataset SHOULD be serialized as a _JSON-LD document_.

.Anatomy of JSON-LD document representing the dataset
[source,json]
----
"@id": ..., <1>
<2>
"@graph": [
    ... <3>
]
----
<1> The IRI of the dataset.
<2> Metadata about the dataset. These statements are contained in the default graph.
<3> The data graph object. These statements are contained in the data graph.

== Metadata

The IRI of the dataset -- i.e. the value of the top-level `@id` -- is RECOMMENDED to be a UUIDv4 encoded as URN using the `uuid` namespace.

Furthermore, the following metadata properties SHOULD be provided by each dataset:

|===
| Label | IRI | Type | Multivalued | Description

| Issued
| `dcterms:issued`
| `xsd:date`
| no
| Date the dataset was issued, i.e. start of the period of its validity.

| Publisher
| `dcterms:publisher`
| IRI from https://modellen.netbeheernederland.nl/controlled-vocabularies/market-parties[Market Parties]
| no
| The publisher of the dataset.

| Conforms to
| `dcterms:conformsTo`
| IRI or `xsd:anyURI`
| yes
| Standards the dataset conforms. This SHOULD at least include the (version of the) profile or data model this data complies with.

| References
| `dcterms:references`
| IRI
| yes
| Other datasets or data products this dataset references (depends on). For any non-boundary datasets this is the `@id` of the boundary dataset being referred to.
|===

=== Validation

The metadata requirements have been encoded as constraints in the {dataset-metadata-shacl-url}[Dataset Metadata SHACL] which can be used to automatically validate whether datasets satisfy the metadata requirements.

CAUTION: SHACL validators expect graphs, not RDF datasets. When an RDF dataset is passed as data graph to validate, many validators will use its default graph.
